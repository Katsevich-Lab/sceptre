### F2 — P2: large native owners still cross unprotected R return allocations

This is a **systemic lifetime boundary gap**, rather than three unrelated symptoms. The successful bounded count/mitochondrial repair establishes a sound native-only compute phase, but the same discipline is not yet present in retained calibration producers and inference return conversion.

| Location at pin | Live C++ storage | R allocation boundary while that storage remains live |

A raw R allocation error can longjmp past these native destructors, leaving malloc storage unowned until process exit. The candidate-space vector can be substantial. Checked cardinality does not establish that a later R allocation succeeds. This is a source-confirmed failure-path concern, **not** an executed real-OOM reproduction or an ordinary numerical failure claim.
- **Baseline comparison:** original `src/negative_control_functions.cpp:32-33,53` and `148-151` have the same live-owner return allocations; original `src/low_level_full_test.cpp:105,130-137` keeps `null_statistics` alive across result-list construction. - **Independence and scope:** this was localized after direct source tracing and before consulting prior unit reports. The prior CL2 closure expressly limits its guarantee to the new count/mitochondrial copies; it does not claim these package-wide owners safe. Its narrow closure and the protected NULL-XPtr draw-bank repair remain valid. The prior senior reviewer independently confirmed the same owner/allocation paths survive the separate CL4 `dc093d2` successor, under renamed symbols; that peer confirmation is not a review of post-pin source by this reviewer.
- **Direction:** use a narrow phase-order or protected conversion repair. Create/materialize R-owned input/output buffers before native owners where practical, compute in an R-call-free inner scope, and end native owners before return/copy/preservation. Where exact-size output requires a protected conversion, the native owners must exist outside the protected callback, and the unwind continuation must be established before those owners; wrapping an entire computation with callback-local owners does not solve longjmp cleanup. Preserve loop/draw order, selected/reversed null segment, numerical fallback and schema; no catch-all fallback or allocation framework is warranted.
- **Safe verification seam:** test-only interposition of actual candidate-source R allocation/coercion/materialization/preservation boundaries and native allocators, bounded tiny inputs, live-owner counters, raw-R-error and `bad_alloc` cases, exact successful outputs/RNG, and an intentionally unsafe-order negative control. ## Architectural assessment

### Responsibilities and dependency direction

The central design is cohesive. The S4 wrappers own public validation, workflow flags and successful result/cache commits. `prepare_analysis_context()` constructs transient state rather than inventing a replacement saved object. `analysis_context.R` owns source/analysis/NT/fit coordinates; `storage.R` owns representation-specific access and private ondisc calls; fitting and score preparation receive aligned ordinary arrays; workers express actual reuse domains; result functions work with plain tables and explicit settings. `execution.R` shares worker mechanics without imposing a common statistical inner loop. There is no backend registry, method class hierarchy, plugin facade, new guide cache, or unused method framework.

The four workers are justified duplication: shared versus guide-specific response fits, crossed with permutation versus CRT bank/reuse scope. Their small native call blocks are easier to inspect than a flag-driven universal worker. The actual private QC/calibration parts and three result adapters also have concrete pipeline callers. I do not recommend deleting these solely because they forward to smaller functions. Conversely, F4 is actual unused computation, and CL4's dead code has no production-consumer reason.

The important systemic weakness is **lifetime/return ownership**, F2: a good invariant has been implemented in some kernels but is absent from other substantial native-return paths. The result-table consumer assumption in F1 is another cross-module contract gap: optional diagnostics have legitimate missingness, while a consumer treats arbitrary missingness as invalid scientific rows. Both need small explicit contracts and boundary regressions, rather than more architecture layers.

### Coordinates, ordering and one-test trace

An independent source trace with analysis source columns `(2,4,5,8,11)`, raw treatment membership `(5,4)`, and NT source groups `(8)` and `(2,11)` produces canonical treatment analysis positions `(2,3)` and ordered NT pool `(4,1,5)`. NT discovery composes fit source columns `(4,5,8,2,11)` and observed fit positions `(1,2)`. The response extraction and source-row design subsetting take that same composed order. `drop=FALSE` retains an intercept-only matrix. NT calibration uses the ordered NT-only pool and translates observed membership into that local view once. Complement fits use the analysis universe.

The actual code path is `run_discovery_analysis()` -> `analyze_association_pairs()` -> prepared context -> one of two plans -> one of four explicit workers -> `fit_response()` / `prepare_score_components()` -> Rcpp boundary -> observed/null score -> selected tail -> native record -> pair assembly -> grouping/finalization. `tests/testthat/test-refactor-indexing.R` gives an inspectable numerical coordinate example, but it does not excuse F3's incorrect eigenbasis contract.

The native observed boundary validates and converts one-based R positions once; synthetic banks are already zero-based. Fisher-Yates/hybrid consumers take a fixed treatment-count prefix; CRT takes every member of the current variable-cardinality row. That is the meaning of `use_all_cells`, not “all assay cells.” Low-MOI calibration concatenates NT memberships; high-MOI calibration unions them. Ordered request row IDs and row splits retain request identity even when QC scans are response-sorted. Final output sorting is the existing p-value/response ordering; it is not request-order output, and complete-gather tie order still requires the disclosed consumer plan.

### Fit/cache/draw/result scope

- Permutation generates one complete B1+B2+B3 bank before response traversal. Shared-view fits/scores are reused per response; NT discovery fits each treatment-plus-NT view and does not persist those fits.
- CRT first prepares missing shared response fits, then visits guides. Each guide fits assignment probabilities and generates its full bank once before reading its responses. NT-discovery response fits are guide-specific. This preserves both the response prepass and guide-level draw sharing, rather than merely producing similar final numbers.
- Cache records retain coefficients/dispersion only. Supported parameter changes compare the actual full source design plus control flag; low-MOI assignment-setting changes and retained-cell changes invalidate fits. NT calibration fits and NT discovery fits are separated by actual view scope. No persistent row/design/score/bank/per-guide-view cache was introduced. Direct arbitrary slot mutation is outside those supported setter guarantees.
- Native stage selection keeps the .02 threshold, separate B1/B2/B3 draw segments, reached-only skew-normal minimum, accepted-fit sentinel and B3=0 fallback behavior. It does not redraw/reseed at a stage boundary. The tail's selected vector can be sorted/reversed by skew-normal evaluation. These are necessary numerical contracts; C1 must explain them concisely rather than leave future contributors to infer them from loops.
- Standard calibration/discovery integrate and correct after gathering the complete family; power groups only. Nuclear/pod output follows the actual raw Parquet consumer boundary and excludes significance at script output. Failed-QC rows are restored before final family processing. The diagnostic plot bug is a downstream consumer defect, not a change to that assembly.

### Storage, import and ownership

The representation boundary is concrete and useful: response access materializes one complete source row, owned count kernels use stored-position presence (including explicit zeros), import covariates use loaded values greater than .5, logical stored-entry conversion differs deliberately from vector aggregation, and backed construction retains integer coercion and shared import IDs. Owned Cell Ranger/Parse coordinates reject repeated file coordinates per Eugene's explicit choice; valid triplet duplicate and guide-metadata multiplicity are separate contracts. External ondisc parsing remains outside that owned parser policy.

The new count kernels prepare R objects/materialize pointers first, make native coordinate/scratch copies in an R-call-free inner scope, and return only after owners end. Disposable R copies are localized to external ondisc calls that can decrement coordinates. This is substantially easier to reason about than distributed mutation defenses. The sparse conversion's explicit constructor ownership flags and defensive slot copies are understandable; their measured total cost still needs disposition. Dense general conversion correctly prevents triangular/symmetric inference from discarding input entries. B6 cannot yet be accepted on the same grounds because its mathematical sum equality is insufficient for platform-specific accumulation parity.
